# issue-linker — 구현 이슈에 근거 연결

## 역할

파트 레포의 구현 이슈에 **관련 논의 이슈, 문서 절, API, 다른 파트 이슈** 링크를 모아 댓글로 남긴다. 이슈를 쪼개거나 담당자·일정을 제안하지 않는다.

## 실행 시점

- 파트 레포에 구현 이슈를 만든 직후
- 다른 파트에 작업을 요청하는 이슈를 만들 때

## 입력

- 구현 이슈 URL (예: `BE 레포#12 알림 목록 API 구현`)

## 읽을 문서

1. [AGENTS.md](../../AGENTS.md)
2. 구현 이슈 본문
3. [결정 모음](../decisions/issue-decisions.md) 이슈 표와 관련 절
4. [PROJECT_CONTEXT](../context/PROJECT_CONTEXT.md)의 관련 장, 버전별 기능 분류
5. [API 명세](../api/api-spec.md)의 엔드포인트 한눈에 보기
6. 다른 파트 레포의 열린 이슈 제목 (도구가 조회할 수 있을 때)

## 절차

1. 이슈 제목·본문에서 기능 키워드(화면 ID, API 경로, 도메인명)를 뽑는다.
2. 키워드로 결정 모음·기준 문서·API 명세의 관련 절을 찾는다.
3. 기능의 버전 분류를 확인한다.
4. 같은 기능을 다루는 다른 파트 이슈가 있으면 서로 링크할 후보로 제시한다. (예: FE 알림 화면 ↔ BE 알림 목록 API)
5. 문서끼리 다르게 적힌 부분을 발견하면 consistency-checker 실행을 권한다.

## 출력: 이슈 댓글

```markdown
## 관련 자료

- 버전: v2 (PROJECT_CONTEXT 버전별 기능 분류)
- 논의 결론: wiki #33 알림 기능 정책 → 결정 모음 #33-7 알림 보관 정책
- 기준 문서: PROJECT_CONTEXT 10장 알림 > 조회·읽음·보관
- API: `GET /api/v1/notifications` (API 명세 8장)
- 연결할 다른 파트 이슈: FE#8 알림 화면 (후보)

### 확인 필요
- API 명세 검토 메모 10: 알림 목록만 snake_case
```

## 하지 않는 것

- 하위 이슈 생성, 체크리스트로 태스크 분할, 담당자·마감일 제안을 하지 않는다.
- 다른 파트 이슈에 직접 댓글을 달거나 관계를 설정하지 않는다. 후보만 제시한다.
