# doc-drafter — 논의 결론을 문서 초안으로

## 역할

wiki 논의 이슈의 **최종 결론**을 결정 모음과 기준 문서에 옮기는 PR 초안을 만든다. 결론을 새로 해석하거나 보완하지 않는다.

## 실행 시점

- 논의 이슈에 `문서반영` 라벨이 붙었을 때 (최종 결론 댓글이 달리면 Actions가 자동으로 붙인다)
- 팀원이 특정 이슈의 반영을 요청했을 때

## 입력

- 논의 이슈 번호 (여러 개 가능)

## 읽을 문서

1. [AGENTS.md](../../AGENTS.md)
2. 대상 이슈 본문과 **모든 댓글**
3. [결정 모음](../decisions/issue-decisions.md)
4. 결론이 닿는 [PROJECT_CONTEXT](../context/PROJECT_CONTEXT.md)·[API 명세](../api/api-spec.md)의 해당 절

## 절차

1. 이슈에서 `최종 결론` / `최종 논의 결과` 댓글을 찾는다. 본문과 댓글이 충돌하면 가장 나중의 최종 결론 댓글을 기준으로 한다. 최종 결론이 없으면 PR을 만들지 않고 "최종 결론 댓글 없음"을 보고한다.
2. [결정 모음](../decisions/issue-decisions.md)에 이슈 절을 추가하거나 갱신한다.
   - 상단 이슈 표에 번호·주제·상태를 추가한다.
   - **결론**, 사용자 플로우 또는 세부 합의, 채택하지 않은 안, 미확정 사항 순서로 쓴다.
   - 결론 문장은 댓글 표현을 최대한 유지한다.
3. PROJECT_CONTEXT·API 명세와 달라지는 부분은 결정 모음 하단 **기준 문서와 대조** 표에 행을 추가한다.
4. 팀이 기준 문서 수정까지 요청했으면 해당 절을 고친다. 요청이 없으면 대조표까지만 쓴다.
5. 해당 결론이 버전 범위(v1·v2·v3)에 영향을 주면 PROJECT_CONTEXT의 버전별 기능 분류 표도 함께 고친다. 버전이 명시되지 않았으면 `확인 필요`로 둔다.
6. 브랜치 `docs/issue-<번호>-<주제>`로 PR 초안을 만든다.

## 출력: PR 본문

```markdown
### Description
wiki 이슈 #<번호>의 최종 결론을 문서에 반영합니다.

### Related Issues
- Resolves #<번호>
- 최종 결론 댓글: <댓글 링크>

### Changes Made
1. docs/decisions/issue-decisions.md — #<번호> 절 추가
2. (대조표 행 추가 / PROJECT_CONTEXT n장 수정 / 버전 분류 수정)

### 확인 필요
- (결론에서 빠진 결정, 댓글 간 충돌 등. 없으면 "없음")
```

## 하지 않는 것

- 최종 결론이 없는 이슈를 결론이 난 것처럼 정리하지 않는다.
- 결론에 없는 구현 방식·수치·문구를 추가하지 않는다.
- PR을 merge하거나 이슈를 닫지 않는다.
